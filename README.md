# 云萌宝伴｜ESP32-S3 异地情感交互机器宠物

这是我在 **2025 年参与的多人协作项目**。我们尝试用 ESP32-S3 做一只能够进行远程互动、语音交互并通过表情和动作反馈状态的机器宠物。

我把当时保留下来的工程整理到了这个仓库，方便展示项目的技术方案和继续恢复代码。**目前我还没有足够完整的历史分工记录，不能准确地把每个功能模块归到自己名下，因此不会把团队工程包装成个人独立开发作品。**

## 我们想实现什么

原工程中包含以下模块；这说明代码存在对应的设计或实现，**不代表所有功能都完成了真机验证**：

| 模块 | 工程中的实现方向 |
| --- | --- |
| 主控 | ESP32-S3 |
| 语音交互 | 通过讯飞语音服务处理交互逻辑 |
| 异地通信 | 基于 MQTT 传递远程互动数据 |
| 表情反馈 | OLED/表情相关显示逻辑 |
| 动作反馈 | 舵机控制逻辑 |
| 留言 | 与留言服务相关的接口逻辑 |

从作品集角度，我更希望这段项目经历说明我们如何尝试将 **嵌入式设备、云端服务与用户交互**结合起来，而不是只罗列硬件和库名。

## 我这次做了哪些归档工作

2026 年，我对留下来的 `ESP-AI-master.zip` 进行了清理和梳理：

- 清除了代码中的历史讯飞 APPID/APISecret/APIKey、MQTT 凭据和固定留言服务地址，改为本地配置文件。
- 仅保留无凭据的配置示例，不上传包含旧密钥的 ZIP 或历史提交。
- 移除了原始 `lib/` 中约 255 MB 的第三方依赖副本、重复库、缓存和构建文件。
- 清理了编辑器自动生成的错误署名及不适用的企业版权模板，**保留 `Base64_Arturo` 等真实第三方作者的版权信息**。
- 整理 PlatformIO 依赖入口和安全检查文档，记录还没解决的版本兼容问题。

这些是**现在可以明确归属于我的归档维护工作**；不能据此推断 2025 年每一部分业务功能都是我独立编写的。

## 技术与工程结构

`ESP32-S3` · `C++` · `PlatformIO` · `MQTT` · `讯飞语音服务` · `OLED` · `舵机控制`

```text
src/                               历史应用代码（已脱敏）
include/project_config.example.h   不含真实凭据的配置模板
platformio.ini                     待核实的构建配置
docs/dependencies.md               依赖与构建限制
docs/security-review.md            安全整理记录
docs/cleanup-manifest.json         文件清理清单
```

如果要尝试恢复构建，需要先复制配置模板并使用**重新生成**的密钥和自己控制的服务地址：

```bash
cp include/project_config.example.h include/project_config.h
pio run -e esp32-s3-devkitc-1
```

**上面只是构建入口，不表示当前已编译成功。** 原工程的 ESP-AI、esp32-eyes 和 ArduinoJson 等依赖存在版本差异，我尚未完成编译和真机回归。详情见 [依赖与构建限制](docs/dependencies.md)。
